# AGENTS.md

Repository-specific knowledge for AI agents working on this codebase.

## What this is

An accuracy-first news platform. Sources are **evidence**; the platform
publishes **original** AI-written articles synthesized from multiple verified
sources. It must never do `source article → paraphrase → publish`.

Non-negotiable product rule: **accuracy outranks speed, volume, SEO and
engagement.** "Not enough verified information to publish" is a valid outcome
and must be implemented as a product behavior, not just an AI prompt.

The spec is delivered in phases. Phase 1 (foundation) is complete; see
`README.md` for the phase table.

## Layout notes

- Source URLs live ONLY in `config/*.yaml`. Never hard-code a source URL in
  application code — this is a spec requirement, enforced by
  `app/services/config_loader.py`.
- `config/international_sources.yaml` must contain **exactly 30** sources;
  `load_international_sources` raises otherwise.
- `app/core/config.py` derives `REPO_ROOT` as `parents[3]` of the file
  (`backend/app/core/config.py`). Inside Docker the repo is mirrored under
  `/repo` so these repo-relative paths resolve the same as on a dev machine.
- `settings.sync_database_url` (psycopg v3) is for Alembic; the app itself uses
  the async `+asyncpg` URL.
- Migrations live in `database/migrations/`, not under `backend/`.
  `alembic.ini` uses `%(here)s/../database/migrations`.
- Autogenerated migrations that include a vector column need
  `import pgvector.sqlalchemy`.

## Database

- PostgreSQL 16 + `pgvector` + `pg_trgm`.
- `CREATE EXTENSION` requires superuser, so extensions are created by
  `infrastructure/docker/postgres-init/01-app-role.sh` at provisioning. The app
  role (`news_app`) is least-privilege. Migration `0001` only verifies presence.
- If the init script's mode is not world-readable the container cannot run it;
  keep it `755`.

## Testing conventions

- Real code paths only; avoid mocks. Integration tests hit a real Postgres and
  skip when none is reachable.
- `pyproject.toml` sets `asyncio_default_fixture_loop_scope` and
  `asyncio_default_test_loop_scope` to `session`. Keep them in sync: the shared
  engine is created at import time, so mixing module-scoped async fixtures with
  function-scoped loops causes "attached to a different loop" errors.

## Security

- Secrets come from env only; `.env` is gitignored (`.env.example` is tracked).
- Admin/ops endpoints use the `X-Admin-Token` header (not `Authorization`).
- Visitor IPs are used only for country resolution and are never stored.
- Containers run as non-root (`appuser`, uid 10001).
